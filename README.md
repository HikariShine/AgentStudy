# OpenClaw系列文章

本仓库记录所有AI完成OpenClaw系列文章

## 目录结构

仓库目录结构如下：

- docs：生成的文章放置的目录，每个系列是一个子目录
  - docs/config: OpenClaw搭建与配置系列
  - docs/use: OpenClaw实战系列
  - docs/tips: OpenClaw问题与技巧系列
  - docs/code: OpenClaw原理分析系列
- skills：文章中用到的各个skill目录
- openclaw.json: 最终的配置文件，去掉的api url和token

## 生成要求

每个子目录包含SUMMARY.md，是这个系列文章摘要，每个二级目录需要对应扩写为一篇文章，扩写时，行文风格参考每个系列的风格要求。每个系列第一篇文章预告全部文章列表，第二篇开始写正文，从SUMMARY.md第一个二级标题开始完成。经过你判断文章内需要插入图片时，可以让用户给一个图片文件，用户也可以主动提供图片文件，需要放入用户指定位置后面或者前面。

生成的文档每一篇都要放入对应系列目录下面，同时创建这篇文章的子目录，相关图片也放入这个子目录，生成文章的md中，使用使用相对路径引用图片即可。例如：docs/config/1/文章标题.md，docs/config/1/图片1.png， docs/config/1/图片2.png，其他素材内容或者生成内容也放入这个目录下。

每篇文章都需要经过用户确认后再标记已完成，这个过程用户会通过本地开放的web版markdown编辑器或者其他途径协同你一起修改文章。

# 风格列表

## 技术教程文

整体风格定位

"保姆级技术教程" —— 不是冷冰冰的文档，而是手把手带你走完的沉浸式体验。作者把自己当成一个坐在你旁边、陪你一起装的朋友。

具体风格特征

1. 开篇三板斧：数据 + 痛点 + 承诺

"千呼万唤始出来！"
"23万Star的项目，大部分人倒在了安装这一步。这不应该。"
"2万字，力求用最精细的步骤教你..."

- 用具体数字建立可信度（2万字、30分钟、23万Star）
- 点出共同痛点（"私信被同一个问题淹没"）
- 给出明确承诺（零基础、手把手、每一步都有截图）

2. 语言风格：口语化 + 情绪饱满

❌ 技术文档写法  ✅ 本文写法

"首先需要安装Homebrew"  "Mac用户看这里。如果你是Windows用户，请跳过这整章"
"请输入密码"  "你打密码的时候，屏幕上不会显示任何字符。没有星号、没有小圆点、什么都没有。这是正常的。"
"Node.js是运行时环境"  "Node.js就像一个翻译官...没有这个翻译官，OpenClaw就是一堆电脑看不懂的天书"

技巧：
- 用"你"直接对话（"我知道你现在恨不得马上开始装"）
- 承认真实情绪（"说实话，我自己第一次装OpenClaw的时候，就是在这一步翻了车"）
- 比喻降低认知门槛（终端=给电脑发微信、npm=应用商店、API Key=健身会员卡）

3. 结构：导航清晰 + 进度可视

阅读导航表格：
你是谁 → 从哪开始看
Mac用户 → 第二章 → 第三章 → 第五章
Windows用户 → 第二章 → 第四章 → 第五章

进度条暗示：
"进度：1/5，环境准备的第一关过了"
"进度：2/5，翻译官到位了"
"进度：3/5，主角登场了。最难的部分已经过了"

4. 心理建设：先打预防针，再给解药

预判焦虑：
"别急着动手。我知道你现在恨不得马上开始装。但请给我5分钟..."
"这行不用管原理，复制粘贴回车就完了。"
"黄色WARN不用管，只有红色ERROR才需要处理"

承认难度但给予信心：
"Windows确实比Mac多几个坑。这是事实。但这些坑全在我的掌控之中"
"你看，命令行不咬人。它只是长得凶。"
"说实话，很多人想象中的'安装部署'是一座大山，走到这才发现——也就两级台阶。"

5. 细节颗粒度：像素级指导

不只是说"安装Node.js"，而是拆解到：
- 按哪几个键打开终端（Command + 空格）
- 密码输入不显示是正常的（提前说明，避免恐慌）
- 截图标注具体位置（红框框出按钮）
- 每个步骤都有验证命令和预期输出

6. 情绪高潮：庆祝用户的成功

最后不是简单"配置完成"，而是：
"深呼吸。配置向导跑完了。"
"这不是一个网页上的聊天工具。这是一个跑在你自己电脑上的AI代理。"
"你成功了。从复制粘贴第一行命令到这一刻，你完成了一件23万人给它点Star的事。"

"从复制粘贴第一行命令，到听见AI第一句回复——这30分钟，你跨过了23万人给它点Star之前的那道门槛。"

把技术成功转化为成就感，让读者觉得自己完成了一件了不起的事。

总结公式

【钩子】数据痛点 + 【导航】清晰路径 + 【陪伴】口语化指导 + 【兜底】常见问题 + 【庆祝】成就感收尾

如果你要写类似文章，建议：
1. 把自己当成读者旁边的真人，不是写文档是给朋友讲
2. 每个步骤都要有"验证"——让读者知道自己做对了
3. 提前说出读者的恐惧——"你可能会觉得...其实..."
4. 结尾给足情绪价值——让他们觉得自己很厉害
