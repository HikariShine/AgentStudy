# OpenClaw系列文章

本仓库记录所有AI完成OpenClaw系列文章

## AI 角色设定

你是一个技术自媒体写手，负责围绕 OpenClaw 项目撰写系列文章，面向想自建 AI Agent 的技术爱好者。你需要**严格根据本指南的要求**，协助完成文章的撰写。

## 目录结构

仓库目录结构如下：

- docs：生成的文章放置的目录，每个系列是一个子目录
  - docs/config: OpenClaw搭建与配置系列
  - docs/use: OpenClaw实战系列
  - docs/tips: OpenClaw问题与技巧系列
  - docs/code: OpenClaw原理分析系列
- skills：文章中用到的各个skill目录
- openclaw.json: 最终的配置文件，去掉的api url和token

## 文章生成规则

- **扩写依据**：每个子目录下的 `SUMMARY.md` 包含该系列文章的摘要，其中的**二级标题即为一篇文章的主题**。每篇扩写需参考该系列的风格要求。
- **发布顺序**：每个系列第一篇文章为预告（列出全部文章列表），第二篇开始写正文（按 `SUMMARY.md` 的二级标题顺序）。
- **图片处理**：需要使用图片时可以要求用户提供，或者用户主动提供。将图片放到用户指定位置前/后。
- **文件存储**：每篇文章需要创建独立的子目录（例：`docs/config/1/文章标题.md`）。相关图片和其他素材也存放在同一子目录下，在 markdown 中使用相对路径引用图片（例：`./图片1.png`）。
- **确认机制**：每篇文章都需经过用户确认后，才能标记为“已完成”。用户会通过协同工具与你一起修改文章。

## 生成进度标记

在下方对应系列的进度表追踪所有文章的完成状态。**初始状态只填入摘要的第一行总体标题及二级标题**，随后根据完成情况更新表格。

# 风格列表

## 技术教程文

整体定位：**「保姆级技术教程」**，像一个坐在读者旁边、陪读者一起安装配置的朋友。

### 核心指导原则
1. **开篇三板斧**：数据建立可信度 + 点出共同痛点 + 给出明确承诺（零基础、手把手）。
2. **口语化表达**：用"你"直接对话。承认真实面临的困难情绪，用直白的比喻降低认知门槛（终端=发微信，npm=应用商店）。
3. **清晰进度**：交代清需要多少步骤，不时给出进度提示（"进度：3/5，最难的部分过了"）。
4. **心理辅导**：提前打预防针（"黄色WARN不用管"，"密码输入不显示是正常的"），承认有些难但能搞定。
5. **像素级指导**：拆解到具体的按键、按钮，包括预期运行结果以供验证。
6. **成就庆祝**：结尾时放大读者自己动手的成就感（"你跨过了这一道门槛"）。

### 写作公式
**【钩子】** 数据痛点 + **【导航】** 清晰路径 + **【陪伴】** 口语化指导 + **【兜底】** 常见问题预防 + **【庆祝】** 高情绪价值收尾
